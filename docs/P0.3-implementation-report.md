## 2. SQLite 表结构与迁移

**库文件**：`media_gateway/data/tasks.db`（WAL；可用 `MOBIUS_TASK_DB` 覆盖）

```sql
CREATE TABLE task_snapshot (
  task_id          TEXT PRIMARY KEY,
  idempotency_key  TEXT NOT NULL,
  payload_hash     TEXT NOT NULL,
  kind             TEXT NOT NULL,
  status           TEXT NOT NULL,
  source           TEXT, user_id TEXT, session_id TEXT, character TEXT, prompt TEXT,
  params_json      TEXT NOT NULL DEFAULT '{}',
  payload_json     TEXT NOT NULL DEFAULT '{}',
  remote_id        TEXT,
  result_json      TEXT,
  error_code       TEXT,
  error_message    TEXT,
  cancel_requested INTEGER NOT NULL DEFAULT 0,
  attempts         INTEGER NOT NULL DEFAULT 0,
  version          INTEGER NOT NULL DEFAULT 0,
  created_at       REAL NOT NULL,
  started_at       REAL,
  finished_at      REAL,
  updated_at       REAL NOT NULL
);
CREATE UNIQUE INDEX ux_task_idem_key ON task_snapshot(idempotency_key);
CREATE INDEX ix_task_status ON task_snapshot(status);

CREATE TABLE outbox (
  seq INTEGER PRIMARY KEY AUTOINCREMENT,
  task_id TEXT NOT NULL,
  op TEXT NOT NULL,              -- task.created / task.updated
  payload_json TEXT NOT NULL,
  created_at REAL NOT NULL,
  sent_at REAL
);
CREATE TABLE schema_meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);
```

迁移脚本：`media_gateway/migrations/001_task_snapshot.sql`（与代码内 `schema_meta.schema_version=1` 一致；
版本不匹配时启动会直接报错，不会静默跑在旧结构上）。

## 3. 状态机转换表

| 当前状态 | 允许迁移到 | 触发者 |
|---|---|---|
| `pending` | `running` / `cancelled` / `submission_unknown` | worker 领取 / 取消 / 恢复证据不足 |
| `running` | `completed` / `failed` / `cancelled` / `submission_unknown` | 执行完成 / 失败 / 取消 / 恢复证据不足 |
| `completed` | —（终态） | — |
| `failed` | —（终态） | — |
| `cancelled` | —（终态） | — |
| `submission_unknown` | —（终态，**禁止自动重提**） | — |

旧词汇读取兼容：`queued→pending`、`succeeded→completed`、`canceled→cancelled`。
非法迁移在 `finish()` 中抛 `ValueError`；重复 `finish()` 是幂等的（不覆盖首次结果）。

**关键规则（来自审查意见）**：恢复时若无法证明任务“未执行”（ComfyUI 无历史也无队列、或崩溃发生在记录
`prompt_id` 之前），进入 `submission_unknown`，**绝不自动重新提交**，避免重复消耗 GPU。

## 4. 测试与故障注入结果

### 4.1 单元测试（`media_gateway/test_async_tasks.py`）

```
37 通过，0 失败
```

覆盖：schema、状态机合法/非法迁移、幂等四种组合、**事务回滚注入**（任务与 outbox 一起回滚）、
claim 原子性、finish 幂等、取消语义、恢复四分支、outbox 顺序投递与失败重试、重开数据库持久性。

### 4.2 端到端验收（`tests/test_p0_3_acceptance.py`，真实网关 + ComfyUI）

```
12 通过，0 失败
submit 时延 199~583ms（要求 <3000ms）
pending/running -> completed
同 key 同 payload 返回原任务（idempotent_hit=true）
同 key 异 payload -> 冲突
任务与 outbox 均已落库
```

### 4.3 故障注入：执行中杀网关

| 步骤 | 观察 |
|---|---|
| 提交任务，等到 `running` 且已有 `prompt_id` | `g_c4c059b0` / remote `2f88a6c8…` |
| 强杀网关进程 | 库中状态仍为 `running`，`outbox` 未发送 8 条 |
| 重启网关 | 日志：`任务恢复完成：{'active': 1}` / `已重新接管 1 个运行中的任务` |
| 等任务收尾 | `completed`，结果 `mobius_portrait_00058_.png`，**attempts=1（未重复执行）** |
| 事件 | outbox 累积到 9 条（Core 侧接口未授权，保留待投递，无丢失） |

## 5. 未解决风险与回滚

| 风险 | 说明 | 缓解 | 回滚 |
|---|---|---|---|
| Core 上报未落地 | `MOBIUS_CORE_TASK_EVENT_URL` 未配置，outbox 只积累不发送 | P0.4 增加 Core 接收端后自动补投 | 删除 outbox 行或清空配置 |
| 双写一致性 | Core 与 Gateway 状态理论上可分歧 | 设计选择：Core 业务权威，Gateway 执行快照；**不做双向覆盖** | 关闭上报，只保留本地 |
| `submission_unknown` 需人工 | 用户需确认后重新提交 | status 返回 `hint` 字段 | 人工 cancel 后重提 |
| 恢复接管仅覆盖 image | voice 同步执行，无长任务 | 语音路径不进入队列 | — |
| Core 唤醒网关失效 | 今晚实测 `POST /api/media/wake` 未拉起网关，已手工启动 | 待排障（见下） | 保持手工/看门狗拉起 |
| 网关当前手工启动 | 非 Core 管理进程，重启电脑后需 watchdog/手工拉起 | 看门狗会检测端口并拉起 | 恢复 Core 管理 |

**代码回滚**：`media_gateway/server.py.bak3-*` 为改动前备份；`git revert` 本次提交亦可。
**数据回滚**：任务库与旧内存队列无关，删 `media_gateway/data/tasks.db` 即回到“无持久化”状态。
