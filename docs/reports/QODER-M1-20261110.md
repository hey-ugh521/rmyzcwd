# Qoder M1 实施任务单 — Core 权威任务生命周期

> 依据：`docs/adr/ADR-007-task-ownership.md`（Accepted，2026-11-10）
> 前置：main `2190f47`（含 T1–T9 + ADR-007/M1 任务单）；生产已升级到 `e4f04a7` 并运行
> 约束：本任务不碰生产、不推 main、不改 LangBot 协议；完成后交 Lead 验收再合并

## 0. 目标

把任务业务状态收敛为 **Core 唯一 owner**，Gateway 只做执行（执行队列/outbox 属传输层），消灭 `task_snapshot` 与 `tasks` 双写。分 3 个提交/阶段，可独立回滚。

已确认参数（ADR-007 §9）：

- Core 分配 `task_id`；调用方只带 `idempotency_key` + payload
- 租约 60s，执行器 30s 续约；过期 Core 置 `failed`（`lease_expired`）
- `submission_unknown` 保留人工确认；24h 未确认转 `failed`（`submission_unknown_timeout`）
- Gateway 旧任务查询接口代理 Core，保留 1 个 release 后移除

## 1. M1a — Core 权威 API 与 schema

文件（建议）：
- `core/store.py`、`core/server.py`（新 API）、`core/migrations/` 或等价 migration runner
- `media_gateway/migrations/` 若需要迁移 task_snapshot

改动：
1. Core `tasks` 表增加/统一字段：`idempotency_key`（唯一索引）、`payload_hash`、`execution_id`、`error_code`、`attempts`、`lease_owner`、`lease_expires_at`、`cancel_requested`、`version`、`payload_json`；PG 迁移脚本 + `schema_version` 记录（参考 ADR-003；SQLite fallback 同步 schema）。
2. 新 API（与现有 Core 鉴权一致）：
   - `POST /v1/tasks`：创建/幂等命中；同 key 同 payload 返回原任务，异 payload 409；返回 `{task_id,status,idempotent_hit}`。
   - `POST /v1/tasks/{task_id}/events`：执行事件（seq 幂等、合法状态转移校验）；Core 为唯一状态写入者。
   - `GET /v1/tasks/{id}`、`GET /v1/tasks`：查询。
   - `POST /v1/tasks/{id}/cancel`：写 `cancel_requested`，终态由执行确认。
3. 状态机遵守 ADR-002；`submission_unknown` 独立终态；非法转移拒绝。
4. 单测/契约测试（不依赖生产 PG）：创建/幂等/冲突/事件/状态机/迁移。

验收：`pytest` 等价脚本全绿；Core API 在临时 PG/SQLite 上通过；迁移可从空库/旧库升级。

## 2. M1b — Gateway 提交与查询切换到 Core

文件：`media_gateway/server.py`、`media_gateway/pg_taskstore.py`、`media_gateway/taskstore.py`、LangBot MCP 工具相关。

改动：
1. 提交流程：Gateway MCP/REST 收到提交 → 调 Core `POST /v1/tasks`（转发 idempotency_key/payload/source/user/session/character）→ 用返回的 `task_id` 作为业务 id；执行侧另存 `execution_id`（Comfy prompt_id）。
2. 业务状态只写 Core：Gateway 不再把 pending/running/succeeded/failed/canceled 写入自己的对外状态；`task_snapshot` 仅保留执行私有字段/迁移期临时账本。
3. Gateway `/api/tasks*` 改为代理 Core（标记 deprecated，1 个 release 后移除）；MCP `comfyui_task_status` 等响应结构保持 `task_id/status/result/error` 兼容。
4. Core 不可用时 fail closed：返回明确错误，不落本地业务状态（避免又变双源）。
5. 幂等命中由 Core 返回；Gateway 不做本地幂等判定。
6. 契约测试：MCP 提交两次同 key → 同 task；异 payload → 409；查询三处一致（Core/Console/Gateway 代理）。

验收：LangBot 主链路（提交→轮询→结果）不改协议即通过；Gateway 无业务状态写入口。

## 3. M1c — 恢复、取消与双写消除

改动：
1. 租约续约：Gateway worker 每 30s 向 Core 续约；Core 过期置 `failed(lease_expired)`。
2. 恢复：Core 重启/Gateway 重启后，Gateway 查 Core `running` 任务，按 `execution_id` 探测 ComfyUI 历史并上报；Core 收敛为终态，禁止永久 running。
3. 取消竞争：Core `cancel_requested`；Gateway 调 Comfy 中断；完成先到则 `succeeded + cancel_requested=true`；不新增第二终态。
4. 迟到产物/`submission_unknown`：按 ADR-007 策略归档/人工确认；24h 超时转 failed。
5. 删除双写：Gateway 不再写任务业务状态；迁移完成后清理 `task_snapshot` 业务列或整表（保留 outbox 传输）；更新 `ARCHITECTURE-v1.1.md`、`ARCHITECTURE-QUALITY.md`、`STATUS.md`、ADR-007 实现状态。
6. 故障注入测试：杀 Gateway/Core、断网、重复提交、取消竞态、迟到回调。

验收：双写 grep/DB 权限证明；崩溃/取消/幂等测试通过；回滚开关/迁移说明齐全。
