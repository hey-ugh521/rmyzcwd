# M3 实施计划 — 安全与生命周期

> 依据：`docs/adr/ADR-009-lifecycle-security.md`（Proposed）
> 前置：main `3a38f59`（M2 完成、生产已修复）
> 原则：先审计/设计，再改安装器；每阶段可独立验收；不破坏 M1/M2 契约

## 1. 目标（GAP M3 退出条件）

- G-11 安全边界可实测；
- G-06 干净 Windows 安装/升级/备份/恢复/卸载演练通过；
- 运行路径不依赖 `D:\AI` / Anaconda / 开发目录；
- 安装产物含版本矩阵；卸载策略明确。

## 2. 阶段

### M3a — 生命周期审计 + 安全边界（先做）

任务：
- 审计并文档化：安装路径、运行时依赖、服务启动、secrets、autostart、卸载残留。
- 本机 token 方案：Core 变更类 `/api`/`/v1` + Gateway `/api/*`；Console/launcher 注入；`/mcp` 按 ADR-006。
- secrets SSOT/ACL：唯一数据目录、权限、日志脱敏；移除重复副本策略。
- `user_id` 身份来源收口（本机/受信网关），不再信任外部 body。
- 安全验收脚本/测试：非回环 401、回环无 token 401、带 token 成功、`/mcp` 兼容、日志无密钥。

退出：
- 安全清单测试通过；不影响现有 M1/M2 正常路径；生产/开发配置迁移说明。

### M3b — 生命周期命令 + 备份/恢复

任务：
- `LifecycleManager`：status/backup/restore/upgrade/uninstall。
- 原生便携 PG dump/restore（替代 Docker `ops/pg_backup.py`）；备份 config/secrets/manifest；校验和/保留策略。
- 恢复先 scratch 校验；升级前自动备份；失败回滚 journal。
- 单元 + scratch DB 恢复演练；CI 可跑单元。

退出：
- 备份→恢复→schema/行数校验通过；升级失败自动回滚演练通过。

### M3c — 安装器重做（干净机器）

任务：
- 默认安装/数据布局（ADR-009 §2.1）；路径全部 config/向导。
- 打包便携 Python + 便携 PG（按 PM 决策）；preflight 改为 config 驱动，无开发路径。
- Integration Manager：ComfyUI/LangBot/NapCat/模型可选组件包；首次文本体验不依赖 QQ/GPU。
- 安装 manifest/版本矩阵；卸载默认保留数据；autostart 随安装/卸载接线。
- 安装器签名/完整性（自签→正式证书策略）。

退出：
- Windows Sandbox/VM 干净安装→启动→文本→（可选）生图→重启→历史；无 `D:\AI` 依赖。

### M3d — 升级/卸载/干净机器验收

任务：
- 升级：老版本→新版本→备份→健康检查→回滚；降级走 restore。
- 卸载：保留数据/删除数据两条路径；autostart/开始菜单/服务清理检查。
- 版本矩阵/CHANGELOG/迁移说明；发布 checklist。
- 安全 + 生命周期全清单实测记录。

退出：
- GAP M3 验收清单全绿；可发布候选。

## 3. 测试清单

- `tests/test_m3_lifecycle.py`（备份/恢复/升级 journal，临时 DB）
- `tests/test_m3_security.py`（token/401/CSRF/日志脱敏）
- `ops/lifecycle_verify.py`（scratch 恢复 + 行数/schema 校验）
- 安装演练脚本/清单（Sandbox/VM，手工记录证据）
- 回归：M1 E2E、M2 Provider/资源、网关/Core 现有套件

## 4. 边界

- 不做：多用户/多机、云同步、自动更新服务器（v1.0 单机）。
- 不改：MCP 工具名/响应、M1 任务 owner、M2 Provider 契约。
- 大件（ComfyUI/模型）不打进主安装包；走 Integration Manager。
