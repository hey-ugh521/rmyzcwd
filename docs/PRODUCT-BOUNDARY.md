# Möbius 产品边界（v1.0）

> 状态：已冻结（2026-11-10）
> 决策人：产品经理
> 关联：`ARCHITECTURE-AS-IS.md`、`ARCHITECTURE-GAP.md`、`docs/adr/`
> 说明：本文回答「v1.0 交付什么、不交付什么、给谁用」；不描述内部实现细节。

## 1. 一句话定位

**Möbius：运行在 Windows 本地的个人 AI 多媒体助手。** 统一管理 AI 角色、媒体生成任务和本地算力资源，让用户在不理解底层基础设施的情况下，完成本地 AI 生图/语音，并能可靠地查看、恢复和管理任务。

不是 ComfyUI 启动器，也不是 QQ 机器人套壳。

## 2. 目标用户

| 维度 | v1.0 定义 |
|---|---|
| 用户画像 | 有一定电脑使用能力、希望在本机使用 AI 角色与媒体能力的个人用户；不要求懂 Python/容器/工作流 |
| 使用场景 | 单人、本机、日常创作与角色对话；不面向团队协作或对外服务 |
| 技术前提 | 有一块可用的 NVIDIA GPU；愿意按向导配置自己的模型/工作流目录 |
| 不假设 | 不假设用户会改代码、会读日志、会排查容器/数据库问题 |

## 3. 首发平台与硬件

| 项 | v1.0 承诺 |
|---|---|
| 操作系统 | Windows 10/11 x64 |
| GPU | **NVIDIA 优先**；最低 8 GB 显存（如 RTX 3060/4060/5060 级别），需满足驱动/CUDA 版本要求（安装时检测并给出明确错误） |
| 内存/磁盘 | 建议 32 GB RAM；模型与 ComfyUI 工作流需额外磁盘空间（按实际模型提示） |
| 运行模式 | 单机单用户；默认只监听 `127.0.0.1` |
| 外部依赖 | 允许配置外部 LLM API；ComfyUI/TTS 作为可安装/可接入的媒体运行环境 |
| 明确不支持 | Linux/macOS、多用户 SaaS、分布式集群、AMD/Intel GPU 全兼容、任意第三方工作流自动兼容 |

## 4. 首发入口

**主入口：Windows 桌面应用（安装器 + 启动器 + 桌面控制台）。**

- 用户从桌面应用完成：首次配置、启动/停止、任务中心、角色与模型配置、诊断。
- Console 是同一控制面的管理视图，可内嵌/由桌面应用打开；不要求用户使用浏览器手动访问。
- QQ 是**可选接入**：需要额外安装 NapCat/LangBot 并登录 QQ，不属于首次成功体验的必要条件。
- Open WebUI 等其他入口属于可选集成，不阻塞 v1.0 首发。

> 当前实现与上述目标的差距见 `ARCHITECTURE-GAP.md`（G-01）。

## 5. v1.0 功能范围

### 5.1 承诺

| 能力 | 说明 |
|---|---|
| 安装/升级/卸载 | 安装器负责 Möbius 本体、依赖检测、配置、数据库、启动项；卸载策略明确保留/删除哪些数据 |
| 首次配置 | 向导：模型/工作流目录、LLM API、媒体运行环境、硬件检查 |
| 角色与人格 | 角色卡、人格/宪法、会话绑定 |
| 图片生成 | 自然语言 → 任务 → 进度 → 结果；支持角色预设与基础参数 |
| 任务中心 | 历史、状态、失败原因、取消、重试/恢复（按任务语义） |
| 媒体调度 | 按需启动、预热、休眠、并发/资源约束 |
| 诊断 | 依赖检查、服务健康、一键诊断、可导出的日志/状态 |
| 语音（第二阶段） | TTS 生成与回传；不是首发第一优先 |

### 5.2 媒体优先级

1. **先生图稳定**：任务生命周期、失败恢复、结果可找回，是 v1.0 的主闭环。
2. 语音作为第二阶段能力，复用同一任务/媒体框架；不在生图未稳定前并行承诺。

## 6. 明确不做（v1.0）

- 不做多用户/权限体系/SaaS。
- 不承诺 Linux/macOS 完整支持。
- 不承诺任意 ComfyUI 工作流/任意模型即插即用。
- 不把 QQ、NapCat、LangBot、Open WebUI 等第三方组件的安装成功率计入首发阻塞项（作为可选 Integration）。
- 不追求「Docker-free」口号；若某集成必须 Docker，则明确标为可选 Docker 集成，并在安装器中分开处理。

## 7. 分发边界

采用两层结构，避免把第三方项目硬塞进主安装器：

1. **Möbius Installer**：安装 Möbius 本体（Core、Console/Desktop、Launcher、数据库、配置、启动项），负责升级/卸载/备份。
2. **Integration Manager**：检测/引导 NapCat、LangBot、ComfyUI、TTS、Open WebUI 等外部组件；只做连接、版本检测、健康检查，不替上游做全量安装。

版本必须分开记录并形成兼容性矩阵：

- Möbius 版本
- 第三方组件版本（LangBot/NapCat/ComfyUI/TTS）
- 工作流版本
- 模型/插件版本

## 8. v1.0 发布门槛（目标值，非当前成绩）

| 指标 | 目标 |
|---|---|
| 干净 Windows 安装成功率 | ≥ 95% |
| 首次启动成功 | ≥ 95% |
| 首次成功生成图片 | ≥ 90% |
| 新用户完成首次生成 | ≤ 15 分钟 |
| 非预期数据丢失 | 0 |
| 未解释的永久卡死任务 | 0 |
| 核心功能自动化回归 | 100% 通过 |

> 这些指标需在明确硬件/模型/网络条件下测量；当前项目尚未完成该测量，不能当作已达成。

## 9. 已冻结的产品决策

| ID | 决策 |
|---|---|
| PB-01 | 主入口：Windows 桌面应用；Console 为同一控制面的管理视图 |
| PB-02 | 媒体优先级：先生图稳定，语音第二 |
| PB-03 | 硬件：NVIDIA 优先，明确最低 8GB 显存与检测/报错 |
| PB-04 | 平台：Windows 10/11 x64、单机单用户 |
| PB-05 | QQ 为可选集成，不是首次成功体验的必要条件 |
| PB-06 | 分发：Möbius Installer + Integration Manager 两层；版本矩阵独立记录 |
