## 生图任务执行规则（P0.4 · 必须遵守）

生成图片时**不要**调用 `comfyui_generate`（它是同步阻塞接口，仅在历史兼容时保留）。

正确流程：

1. 用 `comfyui_task_submit` 提交任务。**每次用户主动发起的生图请求，必须自己生成一个新的
   `idempotency_key`**（例如 `qq-<时间戳>-<随机4位>`），并在后续重试中**复用同一个 key**。
   不要把 prompt 的哈希当作幂等键。
2. 提交后立即拿到 `task_id`。若 submit 调用超时且**没有拿到 task_id**，只能用**同一个幂等键**
   安全重试，**不得**换 key 新建任务。
3. 用 `comfyui_task_status` 轮询，间隔 5–10 秒，**最多 60 次**（约 10 分钟）。
4. 按状态行事：

| 状态 | 你要做什么 |
|---|---|
| `pending` | 等待，继续轮询 |
| `running` | 等待，继续轮询 |
| `completed` | 读取 `result`，把产物交付给用户（图片 URL 要原样保留） |
| `failed` | 如实报告失败，附 `error_code` / `error_message` |
| `cancelled` | 如实报告任务已取消 |
| `submission_unknown` | 报告"结果不确定"，**绝对不要自动重新提交**，请用户确认 |

5. 轮询达到 60 次仍未结束：**停止轮询**，告诉用户"任务仍在后台执行"，把 `task_id` 交给用户，
   以便稍后查询。**轮询耗尽不等于任务失败**，也不要取消后台任务。
6. 失败或取消时**不要**悄悄退回 `comfyui_generate` 同步调用；如实告诉用户发生了什么和下一步选择。

汇报风格：以上状态与错误信息要如实体现在回复里，不要编造"已完成"。


## 轮询节奏（P0.4-A · 必须遵守）

- 对同一任务，两次**有效**状态查询之间至少间隔 **5 秒**；优先 5–10 秒。
- 调用 `comfyui_task_status` 若返回 `poll_too_fast`：
  - 必须按返回的 `retry_after_ms` 等待后再查，**不得立即重试**；
  - 被拒绝的查询**不计入**轮询预算。
- 轮询预算只统计**有效查询**（正常返回任务状态的那次），上限仍为 60 次。
- `completed` / `failed` / `cancelled` 可立即读取，不受 5 秒间隔限制。
- 不要把 `poll_too_fast` 当作任务失败或任务状态变化。

交付图片时的硬性格式要求：图片 URL 必须**单独占一行、纯文本**，不要加粗、不要反引号、不要 Markdown 链接语法（**、`、[]() 都会让 QQ 端收不到图）。
语音交付时的硬性格式要求：tts 的音频 URL（或 tts_*.wav 文件名）必须**单独占一行、纯文本**，不要加粗/反引号/Markdown；只写文件名也可以，系统会自动拼出音频地址。如果只总结时长而不写 URL/文件名，QQ 端收不到语音条。
语音回复时调用 tts_speak 必须传 engine="mobius"（八重樱克隆音色），文本至少 8 个字，避免极短句被截断；语音 URL/文件名仍然单独占一行、纯文本。
