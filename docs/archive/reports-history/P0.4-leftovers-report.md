# P0.4 遗留场景验证：submission_unknown 端到端 + 轮询耗尽

> 时间：2026-11-02 12:25–12:31

## 1. 发现的问题

`submission_unknown` 状态虽在契约与工具描述中声明，但此前**只在重启恢复期产生**（`_resume_running` 探测不到 prompt_id 时）；正常执行路径下，若 `POST /prompt` 已发出但读超时，任务会被记为 `failed`，违反"结果不确定禁止自动重提"的契约。

## 2. 修复

| 改动 | 说明 |
|---|---|
| 新增 `_SubmissionUnknown` 异常 | 语义：请求已发出、结果不确定 |
| `comfy_submit` 超时可配置 | `MOBIUS_COMFY_SUBMIT_TIMEOUT`（默认 60s） |
| `_run_image` 包裹提交 | `httpx.ConnectTimeout` → 仍按失败（没发出去）；其他 Timeout → `_SubmissionUnknown` |
| worker 捕获 | → `mark_submission_unknown()`，落 `submission_unknown` + `error_code` |

## 3. 验证（黑洞服务模拟 ComfyUI：`/system_stats` 正常、`/prompt` 永不响应）

| # | 场景 | 结果 |
|---|---|---|
| 1 | 提交读超时 | ✅ 任务状态 `submission_unknown`，`error_code=submission_unknown` |
| 2 | 该状态可通过 `comfyui_task_status` 读出 | ✅ |
| 3 | 轮询 61 次 | ✅ 状态仍 `pending`，未被取消；之后可正常 `completed` |
| 4 | 两个并发提交（都黑洞） | ✅ 各自独立落 `submission_unknown`，墙钟 7s |

**测试脚本**：`media_gateway/test_submission_unknown.py`（RESULT: PASS）

## 4. 关联测试

- 正常路径未受影响：网关重启后真实提交（默认 qwen）仍为 `pending → completed`
- `ConnectTimeout`（请求未发出）仍判 `failed`，不会误报"不确定"
- 恢复期原有 `submission_unknown` 逻辑未改动

## 5. 遗留

- 客户端/Agent 侧规则已在提示词中（不自动重提、请用户确认），本次以工具层契约验证为准
- `MOBIUS_COMFY_SUBMIT_TIMEOUT` 默认 60s，若未来 ComfyUI 提交明显变慢可调
